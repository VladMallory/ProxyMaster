# Bot - Бот для продажи подписок VLESS
- Работает с панелью 3x-ui
- Поддерживает HTTPS редирект для v2raytun/Happ
- Все настройки регулируются в config.go

## 🔧 Решение проблемы с импортом подписок на Android

### Проблема
На Android устройствах приложение Happ не могло корректно импортировать подписки через кнопку "Подключить". Проблема заключалась в том, что:
1. **Сервер возвращал base64-кодированные данные** вместо готовых VLESS/VMESS URL
2. **Happ получал неправильный формат** данных для импорта
3. **Автоматический redirect не работал** на Android

### Решение
Создан улучшенный redirect файл `redirect_happ_test.html` с логикой:

1. **Получение данных подписки** через API endpoint `/api/subscription`
2. **Декодирование base64** конфигураций
3. **Извлечение VLESS/VMESS URL** из декодированных данных
4. **Создание правильного `happ://add/URL`** для импорта
5. **Улучшенное открытие приложения** через скрытые ссылки
6. **Дополнительные кнопки импорта**:
   - 🔗 **Импорт подписки** - для автоматического обновления конфигураций
   - 📄 **Импорт JSON** - для разовых конфигураций

### Технические детали
- **API endpoint**: `https://im.shadowfade.ru:8443/api/subscription?url=SUBSCRIPTION_URL`
- **Base64 декодирование**: Проверка и декодирование ответа сервера
- **Протоколы**: Поддержка VLESS, VMESS, Trojan, Shadowsocks
- **Fallback**: При ошибках используется оригинальный URL подписки
- **Совместимость**: Работает на всех платформах (iOS, Android, Desktop)

### Файлы
- `importRedirect/redirect_happ_test.html` - улучшенный redirect файл
- `app/init.go` - добавлен API endpoint для получения данных подписки
- `common/functions.go` - временно переключен на тестовый redirect


## Фичи и config.go
### ===Трафик===
- Регулировать конфигурацию можно в `/common/config.go`, раздел `TRAFIC`
- Отключает клиентов если использовали больше трафика чем указано в `TRAFFIC_LIMIT_GB`
- `TRAFFIC_RESET_INTERVAL` - сброс трафика. Например каждый месяц будет обнуляться
- `TRAFFIC_CHECK_INTERVAL` - проверка трафика, превысил ли клиент лимиты

### ===IP BAN===
- Регулировать конфигурацию можно в `/common/config.go`, раздел `IP Ban`
- Рекомендую все настройки оставить по умолчанию. Поскольку там сильно зависит от файла `/usr/local/x-ui/access.log`, панель 3x-ui его чистит каждые 30-60 минут и если вы хотите давать бан меньше чем это время, клиенту будет прилетать повторный бан. Оптимальные настройк снизу. Проверенно, что они работают корректно
   
 ```go
IP_BAN_ENABLED = true                               // Включена ли система IP бана
ACCESS_LOG_PATH = "/usr/local/x-ui/access.log"      // Путь к файлу access.log
IP_ACCUMULATED_PATH = "/var/log/ip_accumulated.log" // Путь к файлу накопленных логов
MAX_IPS_PER_CONFIG = 1                              // Максимальное количество IP адресов на один конфиг (если больше - отключается)
IP_SAVE_INTERVAL = 25                               // Интервал сохранения новых строк в минутах
IP_CHECK_INTERVAL = 25                              // Интервал проверки IP в минутах
IP_BAN_DURATION = 120                               // Длительность бана в минутах (1 час)
IP_COUNTER_RETENTION = 20                           // Время хранения счетчиков IP в минутах (3 часа - в 3 раза больше времени бана для стабильной работы)
IP_CLEANUP_INTERVAL = 1   
   ```

### ===switch_tariff===
- Если отправить в бота команду `/switch_tariff`, то изменяться тарифы с автосписание на тарифный план

### ===АВТОСПИСАНИЕ===
```go
AUTO_BILLING_ENABLED = true    // Включено ли автосписание за каждый день
BALANCE_RECALC_INTERVAL = 1 // Интервал пересчета дней по балансу в минутах (24 часа - страховочная проверка)
TARIFF_MODE_ENABLED = false    // Включен ли режим тарифов (false = автосписание, true = тарифы)
```
- Раньше было обноление каждую минуту, чтобы бот оперативно реагировал, но теперь после каждого пополнения происходит проверка статистику подписки. Чтобы пользователю правильно отображалось время окончания. При этом нагрузка минимальна, так как проверяет только при оплате и раз в сутки. По итогу и нагрузку убрал, и так же корректно бот считывает период подписки

#### Нельзя отключить
- Делается бекап базы данных и востановление из нее при смене сервера
- `common/config.go/TRIAL_BALANCE_AMOUNT = 8` - сумма в рублях, добавляемая на баланс при активации пробного периода

### ===ПРОВЕРКА СОСТОЯНИЯ RESET===
```go
RESET_STATUS_CHECK_ENABLED = true  // Включена ли автоматическая проверка состояния reset
RESET_STATUS_CHECK_INTERVAL = 1440 // Интервал проверки в минутах (1 сутки = 24*60 = 1440)
```
- **Зачем**: Автоматически исправляет "застрявшие" конфиги в состоянии reset
- **Что проверяет**: Email с суффиксом "-reset", флаги Depleted/Exhausted=true, Enable=false
- **Команды админа**: 
  - `/check_reset` - принудительный запуск проверки
  - `/check_depleted` - оптимизированная проверка depleted статусов
  - `/check_depleted_parallel` - параллельная проверка depleted статусов
- **Работает**: В фоновом режиме с настраиваемым интервалом
- **Оптимизации**: Батчинг (групповая обработка) и параллельная обработка с горутинами


# ⚙️ Настройка

### 1. Настройка базы данных PostgreSQL

Бот использует PostgreSQL для хранения данных пользователей. Настройки базы данных находятся в файле `common/postgres.go`:

```go
// Константы для PostgreSQL в common/postgres.go
const (
	PG_HOST     = "localhost"            // Хост PostgreSQL сервера
	PG_PORT     = 5432                   // Порт PostgreSQL (обычно 5432)
	PG_USER     = "vpn_bot_user"         // Имя пользователя БД
	PG_PASSWORD = "your_secure_password" // Пароль пользователя БД
	PG_DBNAME   = "vpn_bot"              // Название базы данных
)
```

**❗ ВАЖНО**: Отредактируйте эти константы в `common/postgres.go` перед запуском бота:
1. **PG_USER** - замените на реального пользователя PostgreSQL
2. **PG_PASSWORD** - замените на реальный пароль
3. **PG_DBNAME** - замените на название вашей базы данных
4. **PG_HOST** - если PostgreSQL на другом сервере, укажите его IP/домен

### 2. Настройка HTTPS для редиректа

Для работы редиректа на v2raytun/Happ нужен HTTPS. Настройка займет 5 минут:

#### Быстрая настройка HTTPS

1. **Установите nginx и certbot:**
   ```bash
   sudo apt update
   sudo apt install -y nginx certbot python3-certbot-nginx
   ```

2. **Получите SSL сертификат:**
   ```bash
   sudo certbot --nginx -d your-domain.com --non-interactive --agree-tos --email your-email@domain.com
   ```

3. **Настройте nginx для проксирования:**
   ```bash
   sudo nano /etc/nginx/sites-enabled/default
   ```

   Замените блок `location /` в секции с вашим доменом на:
   ```nginx
   location / {
       # Проксируем все запросы на локальный сервер на порту 8081
       proxy_pass http://127.0.0.1:8081;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto $scheme;
   }
   ```

4. **Если порт 443 занят (например, xray), измените порт:**
   ```bash
   # В /etc/nginx/sites-enabled/default замените:
   listen 443 ssl; # на:
   listen 8443 ssl;
   ```

5. **Перезапустите nginx:**
   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   ```

6. **Обновите конфигурацию бота:**
   ```go
   // В common/config.go
   REDIRECT_DOMAIN = "your-domain.com:8443" // или :443 если порт свободен
   ```

**Готово!** Теперь редирект работает по HTTPS: `https://your-domain.com:8443/redirect_v2raytun.html`

## 📈 Статистика пользователей

Команда `/users` показывает:

- **Общее количество пользователей**
- **Платящие клиенты** (с процентами)
- **Доступен пробный период** (с процентами)

- **Детальная информация:**
  - Активные конфиги
  - Доступен пробный
  - Потратили пробный, но не платили
  - Общий доход
  - Новые за неделю/месяц
  - Конверсия в платящих

### Фильтрация пользователей

После нажатия "Показать клиентов" доступны кнопки:
- **💰 Платили** - только платящие клиенты
- **🆓 Могут пробовать** - доступен пробный период
- **🔄 Пробовали** - потратили пробный, но не платили
- **❌ Неактивные** - неактивные пользователи

```bash
cd tools
./cleanup_tool
```

## 🚀 Запуск

1. **Клонируйте репозиторий:**
   ```bash
   git clone <your-repo-url>
   cd bot
   ```

2. **Настройте конфигурацию:**
   ```bash
   cp common/config.go.example common/config.go
   # Отредактируйте common/config.go с вашими настройками
   ```

3. **Установите зависимости:**
   ```bash
   go mod tidy
   ```

5. **Установка PostgreSQL**
```bash
sudo apt update
sudo apt install postgresql postgresql-contrib
sudo systemctl start postgresql
sudo systemctl enable postgresql
```

4. **Настройте PostgreSQL** - отредактируйте `common/postgres.go` с реальными данными БД

5. **Запустите бота:**
   ```bash
   go run main.go
   ```

### Альтернативный запуск (сборка)

```bash
# Собрать бинарный файл
go build -o bot main.go

# Запустить
./bot
```
