# Диагностика проблем с подписками

## Проблема: Конфиг не включается после пополнения баланса

### Симптомы
- Пользователь пополняет баланс
- Нажимает `/start`
- Конфиг остается неактивным
- В панели управления подписка показывает статус "Исчерпано"

### Возможные причины

1. **Настройки автосписания**
   - `AUTO_BILLING_ENABLED = false`
   - `TARIFF_MODE_ENABLED = true`

2. **Недостаточный баланс**
   - Баланс меньше `PRICE_PER_DAY`

3. **Ошибки в системе**
   - Ошибка авторизации в панели управления
   - Ошибка создания конфига через API
   - Проблема с базой данных

4. **Конфликт систем**
   - Система проверки истекших подписок отключает конфиги
   - Автосписание не успевает включить их обратно

## Диагностика

### 1. Проверка настроек
```bash
cd /root/bot/tools/debug_subscription_issue
go run main.go
```

Этот инструмент покажет:
- Текущие настройки системы
- Количество истекших подписок
- Пользователей с балансом, но без конфигов
- Рекомендации по исправлению

### 2. Проверка конкретного пользователя
```bash
cd /root/bot/tools/force_enable_config
go run main.go 873925520  # замените на нужный Telegram ID
```

Этот инструмент:
- Проверит настройки пользователя
- Попытается принудительно включить конфиг
- Покажет детальную диагностику

### 3. Проверка логов
Ищите в логах следующие сообщения:
```
ENSURE_CONFIG: ❌ Автосписание отключено
ENSURE_CONFIG: ❌ У пользователя нет баланса
AUTO_BILLING: Ошибка авторизации в панели
AUTO_BILLING: Ошибка создания конфига
EXPIRED_SUBSCRIPTION: Отключение истекшей подписки
```

## Решения

### 1. Исправление настроек
Если `AUTO_BILLING_ENABLED = false` или `TARIFF_MODE_ENABLED = true`:

```go
// В common/config.go
AUTO_BILLING_ENABLED = true
TARIFF_MODE_ENABLED = false
```

### 2. Принудительное включение конфига
Для конкретного пользователя:
```bash
cd /root/bot/tools/force_enable_config
go run main.go <telegram_id>
```

### 3. Перезапуск бота
После изменения настроек:
```bash
cd /root/bot
./bot  # или ваш способ запуска
```

### 4. Проверка панели управления
- Убедитесь, что панель доступна
- Проверьте правильность учетных данных в `config.go`
- Убедитесь, что `INBOUND_ID` корректен

## Улучшения системы

### Автоматическое включение после отключения
Система проверки истекших подписок теперь автоматически проверяет, можно ли включить конфиг обратно, если у пользователя есть баланс:

```go
// В expired_subscription_service.go
if user.Balance > 0 && common.AUTO_BILLING_ENABLED && !common.TARIFF_MODE_ENABLED {
    canAffordDays := int(user.Balance / float64(common.PRICE_PER_DAY))
    if canAffordDays > 0 {
        // Запускаем принудительный пересчет баланса
        common.ForceBalanceRecalculation(user.TelegramID)
    }
}
```

### Увеличение частоты проверок
Пользователь изменил интервал проверки с 5 минут на 1 минуту:
```go
EXPIRED_SUBSCRIPTION_CHECK_INTERVAL = 1 // Проверка каждую минуту
```

## Мониторинг

### Логи для отслеживания
```
EXPIRED_SUBSCRIPTION: Начинаем проверку истекших подписок
EXPIRED_SUBSCRIPTION: Найдена истекшая подписка
EXPIRED_SUBSCRIPTION: У пользователя есть баланс, запускаем принудительный пересчет
AUTO_BILLING: Создан конфиг на X дней для пользователя
ENSURE_CONFIG: Запуск ForceBalanceRecalculation
```

### Уведомления
- Пользователи получают уведомления об истечении подписки
- Администратор получает уведомления об отключении конфигов
- Система автоматически пытается включить конфиги обратно
